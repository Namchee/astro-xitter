title: On Demand Rendering

import { Tabs, TabItem } from '@astrojs/starlight/components';

Astro Xitter supports both static and [on-demand rendering](https://docs.astro.build/en/guides/on-demand-rendering/) mode that allows you to embed tweet dynamically.

However, opting in to on-demand rendering might introducs [cumulative layout shift (CLS)](https://web.dev/articles/cls) as the new content being rendered. To avoid the potential CLS,
this library provides a loading fallback component `XitterLoading` which can be imported in similar fashion to `Xitter`.

To use `XitterLoading`, add [`server:defer`](https://docs.astro.build/en/reference/directives-reference/#serverdefer) to the `Xitter` component, then pass `XitterLoading` as a child to `Xitter`.
The `XitterLoading` component must use the special `fallback` slot.

<Tabs>
    <TabItem label="Astro">
        ```astro
        ---
        import { Xitter, XitterLoading } from 'astro-xitter';
        ---

        <Xitter id={TWEET_ID} server:defer>
          <XitterLoading slot="fallback" />
        </Xitter>
        ```
    </TabItem>

    <TabItem label="MDX">
        ```mdx
        ---
        title: title
        description: description
        ---

        import { Xitter, XitterLoading } from 'astro-xitter';

        <Xitter id={TWEET_ID} server:defer>
          <XitterLoading slot="fallback" />
        </Xitter>
        ```
    </TabItem>
</Tabs>

You can try the on-demand rendering feature by visiting the [on-demand rendering demo](/demo/tweet).
