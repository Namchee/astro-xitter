import { Xitter } from 'astro-xitter';
import { Aside, Tabs, TabItem } from '@astrojs/starlight/components';

While Astro Xitter ships with renderer that mimics the visuals of [X Publish](https://publish.x.com/) as close as possible, it's also possible
to define how the tweet is rendered if the [styling & theming capabilities](/guides/styling) doesn't fit your intended usage.

Custom rendering method can be provided by passing a render function as the first child of `Xitter` component.

<Aside>
    You won't get any access to [the predefined CSS Variables](/guides/styling) if you use custom rendering function.
</Aside>


<Tabs>
    <TabItem label="Astro">
        ```astro
        ---
        import { Xitter } from 'astro-xitter';
        ---

        <Xitter id="<TWEET_ID>">
          {(tweet, status) => <div style={{ padding: '16px', border: '1px solid gray' }}>
            <p style={{ fontFamily: '"Times New Roman"' }}>{tweet.text}</p>

            <p>
              &mdash; {tweet.user.name} (@{tweet.user.screen_name})
            </p>
          </div>}
        </Xitter>
        ```
    </TabItem>

    <TabItem label="MDX">
        ```mdx
        ---
        title: title
        description: description
        ---

        import { Xitter } from 'astro-xitter';

        <Xitter id="<TWEET_ID>">
          {(tweet, status) => <div style={{ padding: '16px', border: '1px solid gray' }}>

            <p>
              &mdash; {tweet.user.name} (@{tweet.user.screen_name})
            </p>
          </div>}
        </Xitter>
        ```
    </TabItem>
</Tabs>

The sample code above will render the following tweet:

<Xitter id="20">
    {(tweet, status) => <div style={{ padding: '16px', border: '1px solid gray' }}>
      <p style={{ fontFamily: '"Times New Roman"' }}>{tweet.text}</p>

      <p>
          &mdash; {tweet.user.name} (@{tweet.user.screen_name})
      </p>
    </div>}
</Xitter>

See the [demo](/demo/showcase) to see this feature in action.


### API Reference

The render function passes 2 parameters:

- The first parameter is the tweet object itself, fetched directly from Twitter API. The object itself might be a complete tweet object or a 'tombstone' that denotes a deleted tweet. If the API request doesn't return an OK response, this parameter will be `null`.
- The second parameter is HTTP status of the request to Twitter API. You can use this field to determine whether the request succeeds or not. Please refer the [error handling](/guides/error) for list of possible errors.

Please refer to the [object schema](https://github.com/Namchee/astro-xitter/blob/master/packages/core/src/types.ts) for complete documentation of the tweet object.

<Aside>
    A request that returns a deleted tweet will still have a `200` status. To check whether a tweet has been deleted or not, check the existence of `tombstone` object instead.

    ```astro
    <Xitter id="<TWEET_ID">
      {(tweet) =>
        tweet.tombstone ? (
          'This tweet has been deleted'
        ) : (
          'Tweet might or might not exist'
      )}
    </Xitter>
    ```
</Aside>
